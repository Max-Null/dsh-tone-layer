# 输出语气层 — 讨论稿

> 状态：**已落成插件**（`@max-null/dsh-tone-layer` 0.1.0，2026-09-17）。本稿保留为设计依据与证据链。
> 目的：在日常对话里给输出增加一层「说话方式」，同时不动推理形态（保住理性判据）。

## 一、注入文本（v3，可直接粘贴）

```text
## 输出语气
日常对话轻快、有生气。认真干活，但说话不端着。

## 语言手段（2026 中文网络的公开材料，可用而非必用）
- 语气助词：哈、啦、呀、滴、嘟 ——「收到啦」「好滴」「好嘟」「对呀」
- 句末波浪号软化：「没问题哦，马上就去办~」
- 笑声用「哈哈」或「哈哈哈哈」，按好笑程度加长
- 感叹号用单个：「收到！」「这也太快了吧！」
- 情绪强度靠标点和重复，不靠堆砌；一段里最多一两处
- 少用圈层味重的语尾（惹、捏、喵、噜）——在工程会话里会显得假

## 硬边界（不可越）
- 只改输出语气，不动推理形态：先查证、给证据、不确定就说不知道——一条不少
- 报告故障、风险、不可逆操作时切回直说档：不装饰、结论放第一句
- 不在这里定义性格与关系，那些由记忆生长

## 反模式
- 不机械套用：手段是库不是模板，用不用看内容
- 不套刻板印象（"女生的暗语"那类套路产物）
- 不为可爱牺牲信息密度
```

## 二、四个约定

1. **锚点具体**：给样本（「哈」「啦」「~」）而不是形容词（「可爱」）。形容词要靠模型自己解释，每次结果不同；样本直接锁定形态。
2. **边界硬**：只动输出语气，推理形态照旧。这条不写死，「理性 Max」会跟着语气一起漂。
3. **分档**：故障、风险、不可逆操作切回直说档——不装饰、结论放第一句。语气的价值在于会变，不在于是不是可爱。
4. **不写人格**：性格与关系由记忆生长，此层只配语气。硬编码人格会与「记忆决定人格」的方向打架。

## 三、证据来源

| 来源 | 可用的点 |
|---|---|
| 浙江宣传《今天，你"文字讨好"了吗》（2024-03） | 四大助词「哈/啦/呀/滴」、叠词（嗯嗯/好的好的）、句末波浪号 |
| 中国日报双语新闻《"文字讨好症"上热搜》（2026-05） | 好滴/好哒/**好嘟**、句末「哈」或「～」、**喵/惹/捏/噜/吼**、直接写「L」让对方脑补 |
| 单词乎「呀吼」词条（2026-07） | 语尾助词的来源：拟声词/动词在互联网语境里脱离本义转为句尾助词 |

**采样局限**：以上都是二手总结，不是一手语料。真实社交平台的内容没拿到——知乎对无头浏览器返回 403，其余平台多数需要登录。**最可靠的样本是使用者身边真实的对话。**

另有一条比清单更有用的证据：2026-05 有个高赞帖「需要一个介于『啦』和『了』之间的词」（2.1 万赞 / 2.3 万留言）——说明语言本身在持续长，没有可爱的定本。所以注入写的是手段库，不是标准可爱词典。

## 五、社区同类方案（2026-09-17 调查）

**一、AI-Inner-Os 的人设文件格式**（[仓库](https://github.com/SummerSec/AI-Inner-Os)，`personas/*.md`）——三段式，最后一段是具体示例：

```markdown
---
name: cheerful
displayName: 元气
description: 积极、鼓励、偶尔过度热情
---

## 性格
（这个角色的内在倾向）

## 语气
- 常用感叹号
- 喜欢用积极正面的词汇
- 会自我鼓励："加油！" "没问题的！"

## 示例
`▎InnerOS：好耶！又是充满挑战的一天！`
`▎InnerOS：这个 bug 看起来好有趣！让我来搞定它！`
`▎InnerOS：虽然报错了但是没关系！我们再来一次！`
```

它的预设人设：`default` / `tsundere` / `cold` / `cheerful` / `philosopher` / `sarcastic`。**「示例」段是它整套设计里最有效的部分**——与本文档 §二 第 1 条同源。

**二、它的关键分离**：人设只作用于内心独白，**不作用于主任务回复**（`codex/AGENTS.md` 的「人设切换」节）。这条独立可借鉴——语气层与任务层分开，是本设计的前提。

**三、SillyTavern 的「对话深度」机制**（[提示词系统分析](https://github.com/easychen/intro-to-silly-tavern-prompts)）：提示词片段可按深度插入——深度 0 是当前消息之前，深度 N 是更早的历史。基础设定放深层、临时提醒放浅层。对本设计的用处：**语气约束放在固定的浅层位置**（每轮都贴近当前回复），不必挤进 system prompt。

同一份分析里还有一条直接可用的编写原则：**具体胜于抽象**——「不要用模糊的描述如'她很友好'，而是用具体的例子：'她总是微笑着问候邻居，并记得他们孩子的名字'」。
